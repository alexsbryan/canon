## 2. How does the implemented frontend organize the whole experience?

### Takeaway

The strongest implemented architecture is **one recognizable object with multiple useful views**, surrounded by small context handoffs and durable work status. There are genuine separation seams—pure setup views, prop-driven render leaves, a centralized invoke wrapper and a backend-owned notebook summary—but also large orchestration components and inconsistent lifetime/error handling.

### Cited Findings

**Application shell, navigation and domain/feature boundaries**

- `App.svelte` owns a closed `AppView` union and derives rail selection; navigation is local reactive state and callbacks in the inspected shell, rather than URL routing. The five rail destinations are Ask, Library, Reflect, Workshop and Settings. It wires cross-feature navigation, keyboard shortcuts, boot/setup, selected conversation and global banners. Features are mostly directory/component boundaries (`library/`, `reading/`, `atlas/`, `deep_research/`, `workshop/`), not separately built applications. [clients/desktop/src/App.svelte:52–92,195–223,474–520,593–717](https://github.com/alexsbryan/commonwealth-ai/blob/e60d53d6f4a4623f6914ce079e875089b9f9942a/clients/desktop/src/App.svelte#L52-L92); [clients/desktop/src/lib/components/NavRail.svelte:5–46](https://github.com/alexsbryan/commonwealth-ai/blob/e60d53d6f4a4623f6914ce079e875089b9f9942a/clients/desktop/src/lib/components/NavRail.svelte#L5-L46).
- **Library is an object home:** it fetches one notebook list, provides a first-notebook empty state, Add sheet, card shelf, status and per-object actions. `NotebookDetail` hosts scoped Ask, Explore, conditional Conflicts, Sources and Settings. Source/settings are in an overflow menu; Ask/Explore and applicable Conflicts are prominent. [clients/desktop/src/lib/components/library/LibraryView.svelte:39–59,121–159,176–239](https://github.com/alexsbryan/commonwealth-ai/blob/e60d53d6f4a4623f6914ce079e875089b9f9942a/clients/desktop/src/lib/components/library/LibraryView.svelte#L121-L239); [clients/desktop/src/lib/components/library/NotebookDetail.svelte:416–440,477–528,580–603](https://github.com/alexsbryan/commonwealth-ai/blob/e60d53d6f4a4623f6914ce079e875089b9f9942a/clients/desktop/src/lib/components/library/NotebookDetail.svelte#L416-L528).
- **Use→explore→ask is implemented:** selecting an atlas subject or source-raised question sets notebook scope, seeds a fresh question and selects Ask. Ask resumes the notebook's latest conversation and is retained in the DOM across its tab changes. An absent map offers an actionable “Make explorable” path, not an unexplained blank graph. [clients/desktop/src/lib/components/library/NotebookDetail.svelte:97–190,238–323,509–577](https://github.com/alexsbryan/commonwealth-ai/blob/e60d53d6f4a4623f6914ce079e875089b9f9942a/clients/desktop/src/lib/components/library/NotebookDetail.svelte#L97-L190).
- **View versus business seam:** the desktop's `notebook_list` command returns a backend-composed `NotebookSummary` list through `TurnClient::corpus_notebooks`, and propagates failure. The current executable body does not fold five data sources in the view/client. Its adjacent historical comment explains that aggregation moved behind `/internal/corpus/notebooks`; the frontend renders the summary and object scope. **Client contracts, errors, state ownership and invalidation**

Plugins have a separate, less-typed entry point. - **Frontend growth is not covered by the inspected size ratchet:** `size_gate` collects `.rs` for crates and selected script extensions only in `scripts/` and `clients/desktop/tests/e2e/scripts`; its instrument is advisory and its change selector excludes normal frontend changes. Physical file lengths reported by local Read are App **1,186**, ChatView **2,500**, AssistantMessage **1,268**, NotebookDetail **1,023**, api.ts **2,804** lines, including comments/blank lines/styles. These are file lengths, not production SLOC or bundle bytes. The root eagerly imports its main surfaces. ### Inferences

- The useful architectural unit is a **journey/context boundary**, not a screen per command: object creation/addition → scoped activity → evidence → conflict or next action → return to object. Tests encode continuity across those boundaries, although no empirical usability evidence was assessed.
- The mature parts reduce duplicate ownership, but the app is not uniformly “thin”: App orchestrates many concerns, ChatView still combines subscriptions, caching, routing, form state and send races, and API/DTO surfaces are broad. A small canon UI should borrow the seams without reproducing the accumulated platform.
- The imperative epoch/reload patterns are adequate evidence for explicit invalidation, not a reason to add a global cache library. For canon, external CLI/MCP writes and interpretation mode would also need to participate in invalidation; that is an adaptation requirement supplied by canon's stated scope.

### Gaps

- No exhaustive audit of all features or event listener cleanup. One visible concern: `initEventListeners` returns unlisteners, while App awaits it without retaining that return and its destroy handler clears other resources; this warrants review before copying the lifecycle pattern wholesale. This is a static concern, not a reproduced leak. [clients/desktop/src/lib/events.ts:26–35,107–108](https://github.com/alexsbryan/commonwealth-ai/blob/e60d53d6f4a4623f6914ce079e875089b9f9942a/clients/desktop/src/lib/events.ts#L26-L35); [clients/desktop/src/App.svelte:234–287,522–528](https://github.com/alexsbryan/commonwealth-ai/blob/e60d53d6f4a4623f6914ce079e875089b9f9942a/clients/desktop/src/App.svelte#L234-L287).
- Source-reading async safety is uneven: `openAtom` checks corpus/atom identity after awaiting, while inspected `openQuote`/`openCitation` have no analogous request-generation check. Rapid overlapping source opens could overwrite a newer selection; not reproduced. [clients/desktop/src/lib/stores/readingSession.svelte.ts:313–366,404–431](https://github.com/alexsbryan/commonwealth-ai/blob/e60d53d6f4a4623f6914ce079e875089b9f9942a/clients/desktop/src/lib/stores/readingSession.svelte.ts#L313-L431).
- No claim that all accessibility rules pass, that all backend DTOs match synthetic fixtures, that actual model answers are correct, or that size/performance is acceptable. Those questions require the missing runtime measurements.

## 3. What should canon borrow, in what order, at what cost—and what should it avoid?

### Takeaway

Borrow seven bounded patterns, with **record-centered continuity and backend-owned meaning** first. These are recommendations conditional on the canon researcher's inventory of existing UI/API seams. They do not authorize a rewrite, new core public API, generated-contract changes, or a switch to the experimental temporal institution reader.

### Cited Findings and ranked recommendations

**Cost convention:** estimates below are engineering judgment for a first bounded journey/pattern using existing canon endpoints, not measured sovereign costs and not the cost of implementing canon's entire product. Days are focused engineer-days including focused tests. Frontend line ranges are rough net authored TS/JS/HTML/CSS, exclude dependencies/generated output/tests, overlap between lessons, and must be re-estimated against canon's actual frontend. Backend additions are separate proposals because Rust headroom is nearly exhausted.

#### 1. BORROW FIRST — One group's record as the workbench context, with actions organized around the object

- **Observed responsibility/evidence:** Library owns shelf→Add→detail; NotebookDetail composes existing Ask/Explore/Conflicts/Sources/Settings around one `notebook.id`, resumes scoped history and offers capability-enabling actions. This is re-parenting useful capabilities, not introducing a separate implementation of each capability. [clients/desktop/src/lib/components/library/LibraryView.svelte:121–159,187–239](https://github.com/alexsbryan/commonwealth-ai/blob/e60d53d6f4a4623f6914ce079e875089b9f9942a/clients/desktop/src/lib/components/library/LibraryView.svelte#L121-L239); [clients/desktop/src/lib/components/library/NotebookDetail.svelte:122–184,416–440,509–585](https://github.com/alexsbryan/commonwealth-ai/blob/e60d53d6f4a4623f6914ce079e875089b9f9942a/clients/desktop/src/lib/components/library/NotebookDetail.svelte#L122-L184).
- **Recommendation for canon:** a first-entry path to start/open a group's record and establish acting identity; once open, persistent record/identity context with coherent routes into review/drafts, authority/seats/rooms/procedures/assent, gaps/conflicts/revisit, assets/draws/rotations, and history/witness. Treat those as candidate groupings for the canon study, not a finalized tab list. Sharing belongs beside the record and its access/provenance context. Agent/model/institution configuration should be reachable from the task that needs it as well as settings.
- **Adoption cost:** 2–4 days / approximately 250–600 net frontend lines for the initial workbench/navigation and one end-to-end record journey, assuming existing views are composed. Completing all listed domains is additional work.
- **Tradeoffs/avoid:** local shell state is cheap but does not inherently support refresh, browser Back or shareable context. Canon's browser entry point should encode durable record/entity destinations in its existing routing mechanism, carrying identifiers rather than copying entire summary objects. Do not copy an icon-only rail whose labels appear only on hover: sovereign's implementation supports screen-reader labels, but visible discoverability for newcomers is still an inference, not proved by those labels. [clients/desktop/src/lib/components/NavRail.svelte:40–85](https://github.com/alexsbryan/commonwealth-ai/blob/e60d53d6f4a4623f6914ce079e875089b9f9942a/clients/desktop/src/lib/components/NavRail.svelte#L40-L85).

#### 2. BORROW FIRST — Evidence is a contextual inspection path with a return trail

- **Observed responsibility/evidence:** source hash/range retrieval, exact-quote mismatch display, reading breadcrumbs, focused passage and cross-view request/consume handoffs. Source absence has an explicit refusal test; it is not silently replaced by another chunk. [clients/desktop/src/lib/stores/readingSession.svelte.ts:343–366,445–487](https://github.com/alexsbryan/commonwealth-ai/blob/e60d53d6f4a4623f6914ce079e875089b9f9942a/clients/desktop/src/lib/stores/readingSession.svelte.ts#L343-L366); [clients/desktop/src/lib/stores/readingSession.test.ts:49–77](https://github.com/alexsbryan/commonwealth-ai/blob/e60d53d6f4a4623f6914ce079e875089b9f9942a/clients/desktop/src/lib/stores/readingSession.test.ts#L49-L77).
- **Recommendation for canon:** review a draft beside its quoted source and proposed record change; follow an authority/assent/procedure/history claim to the exact supporting record entry, then return to the interrupted task. Keep group record, source address and acting identity explicit through the handoff. A compact inspector/breadcrumb can serve both authoring and provenance instead of separate disconnected quotation/history tools.
- **Adoption cost:** 2–4 days / roughly 150–350 frontend lines for one source/record inspector path if retrieval already exists. Any new quotation addressing/storage is separate backend scope, not included.
- **Tradeoffs/avoid:** preserve exact canonical offsets/identities; do not substitute snippets or infer a missing witness. Add stale-request guards before borrowing the store methods (see §2 Gaps). Do not make the UI recalculate institutional authority or evidence validity; display the compatible backend's result and reasons. The experimental temporal reader must remain a separately named opt-in preview with visibly distinct results.

#### 3. BORROW — State follows the lifetime of work; navigation does not own jobs

- **Observed responsibility/evidence:** app-scoped deep-research subscription/result/acknowledgement, sticky per-corpus failures, smallest-fit state tiers, immutable nested updates, explicit membership invalidation and pre-await user feedback. Continuity assertions cover progress and completion while away. [clients/desktop/src/lib/stores/deepResearch.svelte.ts:305–387](https://github.com/alexsbryan/commonwealth-ai/blob/e60d53d6f4a4623f6914ce079e875089b9f9942a/clients/desktop/src/lib/stores/deepResearch.svelte.ts#L305-L387); [clients/desktop/tests/e2e/specs/deep-research-continuity.spec.ts:136–241](https://github.com/alexsbryan/commonwealth-ai/blob/e60d53d6f4a4623f6914ce079e875089b9f9942a/clients/desktop/tests/e2e/specs/deep-research-continuity.spec.ts#L136-L241); [clients/desktop/src/lib/stores/corpusProgress.svelte.ts:53–84,187–203](https://github.com/alexsbryan/commonwealth-ai/blob/e60d53d6f4a4623f6914ce079e875089b9f9942a/clients/desktop/src/lib/stores/corpusProgress.svelte.ts#L53-L84).
- **Recommendation for canon:** local form/draft state at the smallest owner; an explicit record-context owner for shared selections and read snapshots; an app-level job owner for genuinely long quote/model/agent work. Surface operation ID, subject record, progress and terminal reason; retain actionable errors until acknowledged. Mark “submitting” immediately, but show an append/undo as committed only after canonical acknowledgement. Refresh relevant derived reads after append, assent, undo or externally detected CLI/MCP changes; scope cache identity by record and interpretation mode.
- **Adoption cost:** 2–4 days / roughly 150–350 frontend lines for one recoverable operation plus targeted invalidation, conditional on an existing status/refresh API. Durable server jobs or new event protocols are outside that estimate.
- **Tradeoffs/avoid:** do not install XState/Immer merely to replicate three booleans. A small reducer and replacement updates may suffice. Do not transplant permanent hidden view trees as the general persistence strategy: sovereign uses CSS keep-alive in App and NotebookDetail, and its chat registry still has a narrower lifetime. Keep DOM lifetime, job lifetime and persisted-record lifetime distinct. Errors, stale signal and empty results need separate states; cancellation requested is not proof a backend mutation was cancelled.

#### 4. BORROW — A checked, narrow transport seam; the domain remains backend-owned

- **Observed responsibility/evidence:** generated command-name/key drift guard plus one invoke wrapper; separate plugin escape hatch; notebook aggregation served behind one backend route; pure structured-error normalization. [clients/desktop/src/lib/invoke.ts:10–60](https://github.com/alexsbryan/commonwealth-ai/blob/e60d53d6f4a4623f6914ce079e875089b9f9942a/clients/desktop/src/lib/invoke.ts#L10-L60); [clients/desktop/src-tauri/src/commands/corpus.rs:143–169](https://github.com/alexsbryan/commonwealth-ai/blob/e60d53d6f4a4623f6914ce079e875089b9f9942a/clients/desktop/src-tauri/src/commands/corpus.rs#L143-L169).
- **Recommendation for canon:** use one browser HTTP adapter over the existing local server, with explicit request/response/error shapes and fixture examples for the few journey endpoints actually used. Views express intents and render returned state/reasons; core interpretation, authority, append legality and undo semantics remain in canon's existing compatible owner. UI/CLI/MCP should reach the same meanings rather than share duplicated frontend interpretations. Treat temporal-preview results as a different explicit mode, including cache isolation.
- **Adoption cost:** 1–2 days / roughly 80–180 frontend lines for a few endpoints and normalized errors; 2–4 days if implementing generation/drift tooling. No assumed core/CLI/record contract modification or blessing.
- **Tradeoffs/avoid:** sovereign's `unknown` values and caller-asserted returns are not enough to promise wire safety; its mixed raw/checked APIs show how migration fragments. Prefer a small accurate adapter to a new 260-command “universal platform”. Do not add backend aggregation just to imitate notebook_list if canon already provides the required read; existing surface inventory decides.

#### 5. BORROW — Pure views with thin controllers; model setup is an explicit capability journey

- **Observed responsibility/evidence:** real `SetupPlanView`/`SetupScreen` are driven both by the live read/progress controllers and the fixture gallery. Phase, failure, model provenance and retry are props; backend work stays in the controller/API. [clients/desktop/src/lib/setup/SetupFlow.svelte:105–148](https://github.com/alexsbryan/commonwealth-ai/blob/e60d53d6f4a4623f6914ce079e875089b9f9942a/clients/desktop/src/lib/setup/SetupFlow.svelte#L105-L148); [clients/desktop/src/lib/setup/ScreenGallery.svelte:17–60](https://github.com/alexsbryan/commonwealth-ai/blob/e60d53d6f4a4623f6914ce079e875089b9f9942a/clients/desktop/src/lib/setup/ScreenGallery.svelte#L17-L60).
- **Recommendation for canon:** isolate reusable record header, source quotation, change preview, authority explanation, job status and model-configuration views from transport orchestration. Drive their pending/empty/refused/stale/ready states with small fixtures. Let users open/read/manual-author a record before configuring optional models; explain model-assisted quotation/agent capabilities and route from the relevant task into setup, then return. Show provider/model choice, local/remote boundary and failure remedy from actual configuration/status, not invented defaults.
- **Adoption cost:** 1–2 days / roughly 100–250 frontend lines for extracting one existing view plus representative fixtures; another 2–3 days for a model setup/return journey if needed.
- **Tradeoffs/avoid:** sovereign gates its main entry through setup, including model acquisition; canon should not inherit mandatory multi-model downloads or Tauri plugins. A fixture gallery is cheap, but manually copied fixture facts can drift; use captured/typed examples from the existing backend where practical. No need for a new component-package build or Storybook platform to obtain the seam.

#### 6. BORROW — Test cross-boundary journeys and shared accessibility behavior, with explicit fidelity

- **Observed responsibility/evidence:** deterministic bridge tests assert navigation continuity, no duplicate start and source refusal; CI actually invokes the synthetic suites. Shared modal focus behavior is used in a real join dialog. The axe report's nonblocking status and real-backend CI exclusion are explicit limitations. [clients/desktop/tests/e2e/specs/notebook-detail.spec.ts:132–204](https://github.com/alexsbryan/commonwealth-ai/blob/e60d53d6f4a4623f6914ce079e875089b9f9942a/clients/desktop/tests/e2e/specs/notebook-detail.spec.ts#L132-L204); [.github/workflows/ci.yml:304–338](https://github.com/alexsbryan/commonwealth-ai/blob/e60d53d6f4a4623f6914ce079e875089b9f9942a/.github/workflows/ci.yml#L304-L338); [clients/chat-ui/src/actions/dialog-focus.ts:46–114](https://github.com/alexsbryan/commonwealth-ai/blob/e60d53d6f4a4623f6914ce079e875089b9f9942a/clients/chat-ui/src/actions/dialog-focus.ts#L46-L114).
- **Recommendation for canon:** prioritize a few fixture-record journeys: open/create→identity→inspect source→draft/change preview→append→history→undo; navigate away from async work and return; encounter denied authority/model failure and recover; distinguish ordinary interpretation from explicit institutional preview. Test the UI against a disposable actual local server for canonical append/undo semantics, and use synthetic responses for deterministic timing/error/race states. Preserve keyboard focus after dialogs, readable labels, live completion/error announcements and reduced-motion behavior as shared small primitives.
- **Adoption cost:** 1–3 days for the first meaningful journey and basic focus/status primitives; about 80–200 frontend lines plus test code. New browser-test infrastructure is additional if canon lacks it.
- **Tradeoffs/avoid:** synthetic events prove rendering/reaction, not governance semantics or model correctness. Sovereign's own quality document records a hardware fixture with the wrong field shape that made a guard ineffective: do not let hand-written mock DTOs become an independent contract. [clients/desktop/QUALITY_SURFACE.md:196–205](https://github.com/alexsbryan/commonwealth-ai/blob/e60d53d6f4a4623f6914ce079e875089b9f9942a/clients/desktop/QUALITY_SURFACE.md#L196-L205). Do not equate warning-clean compilation or an always-zero axe report with accessible completion of all journeys; adopt small targeted keyboard checks rather than importing the complete soak/demo/sabotage apparatus immediately.

#### 7. BORROW THE CAUTION — Account for frontend growth separately; collapse ownership before splitting files

- **Observed responsibility/evidence:** current size accounting measures Rust and designated script trees, not normal Svelte/TS/CSS frontend source; the size instrument is advisory. App, ChatView and api.ts are large, and the shared source package still duplicates dependency-bearing modules. A stack that has many tests can still accumulate a substantial frontend. [quality/xtask/src/size_gate.rs:54–60,429–441](https://github.com/alexsbryan/commonwealth-ai/blob/e60d53d6f4a4623f6914ce079e875089b9f9942a/quality/xtask/src/size_gate.rs#L54-L60); [quality/instruments.toml:347–359](https://github.com/alexsbryan/commonwealth-ai/blob/e60d53d6f4a4623f6914ce079e875089b9f9942a/quality/instruments.toml#L347-L359); [clients/chat-ui/src/index.ts:13–24](https://github.com/alexsbryan/commonwealth-ai/blob/e60d53d6f4a4623f6914ce079e875089b9f9942a/clients/chat-ui/src/index.ts#L13-L24).
- **Recommendation for canon:** before any rewrite, record authored frontend source/test/generated counts, largest files, third-party runtime dependencies, embedded asset/bundle bytes and cold-load/readiness costs separately from Rust budgets. Price each proposed journey by net new code and what existing UI it replaces. Start with a bounded workbench slice and existing browser delivery; demand a separate justification for new runtime libraries or an app platform. Make the budget instrument cover JS/TS/Svelte/HTML/CSS actually shipped, not just a Rust crate wrapper.
- **Adoption cost:** 0.5–1 day / perhaps 30–80 tooling lines for simple source/dependency/asset accounting using existing scripts; performance/bundle measurements and any new hard gate require calibration, not an invented cap.
- **Tradeoffs/avoid:** line counts are not bundle size or complexity, and shrinking source by adding dependencies is not automatically a win. Do not turn frontend extraction into a second 2,500-line coordinator or a monolithic API module; one owner per flow beats moving the same orchestration into many files. Import the architectural lesson, not sovereign's daemon supervisor, updater, mesh-app registry, multi-model bootstrap, source-package aliases and full desktop dependency tree.

### Inferences: bounded adoption sequence and product implications

1. **Inventory existing canon UI/server seams first** (owned by the canon researcher). Choose one complete record journey and add the workbench context/return paths around it; retain the compatible ordinary interpretation.
2. Add source/change inspection and a clear committed-vs-pending boundary; make authority/assent/history reachable at the point of action. Preserve canonical meaning in the existing Rust owner; UI composition is not permission to alter generated contracts.
3. Add app-lifetime async status only where actual long work demands it; implement targeted invalidation for appends and external CLI/MCP activity. Keep experimental institutional preview visibly separate and mode-keyed.
4. Add one real-server journey plus cheap deterministic error/continuity/focus checks, and record frontend growth. Expand into remaining group operations, shared assets and agent/model journeys only after the bounded slice is useful and priced.

The navigation lesson is therefore broader than “put every command in a sidebar”: keep a person's **record, identity, evidence and unfinished work** coherent while exposing the next relevant capability. Sovereign's object home, source inspector and task presence are implemented examples of that approach; their value to canon remains a recommendation to validate, not a measured outcome.

### Gaps and decisions the final report must preserve

- Canon feasibility estimates are conditional: this researcher did not audit canon or svrngs. The coordinator should reconcile these proposals with the actual existing browser code, APIs, budgets and ordinary-versus-experimental interpretation boundary before choosing implementation scope.
- No recommendation to adopt Tauri, Svelte, XState, Immer or a query-cache library wholesale. A framework decision requires evidence that the smallest existing frontend cannot serve the scoped journey and an explicit net-size/delivery comparison.
- No code changes, builds, tests, contract blessing, migrations, configuration changes, commits or pushes were performed. Only this research note was added with `apply_patch`; source inspection was static and read-only.
